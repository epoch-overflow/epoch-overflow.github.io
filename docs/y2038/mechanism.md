# 仕組み

## `time_t` と UNIX時間

C言語や POSIX では、時刻を表す型として `time_t` が使われます。多くの処理系で、`time_t` は UNIXエポック（1970-01-01 00:00:00 UTC）からの経過秒数を表す**符号付き整数**です。

かつての32ビット環境では、`time_t` が32ビット幅であることが一般的でした。この場合、表せる範囲は次のとおりです。

- 最小値：−2<sup>31</sup> 秒 → 1901-12-13 20:45:52 UTC
- 最大値：2<sup>31</sup> − 1 秒 → 2038-01-19 03:14:07 UTC

## 桁あふれの様子

```c
#include <stdio.h>
#include <stdint.h>
#include <time.h>

int main(void) {
    int32_t t = INT32_MAX;          /* 2038-01-19 03:14:07 UTC */
    t = (int32_t)((uint32_t)t + 1); /* 1秒進める → 符号が反転する */

    time_t tt = t;
    char buf[64];
    strftime(buf, sizeof buf, "%Y-%m-%d %H:%M:%S", gmtime(&tt));
    printf("%s\n", buf);            /* 1901-12-13 20:45:52 と表示される */
    return 0;
}
```

!!! info "なぜ `uint32_t` を経由するのか"
    C言語では、符号付き整数のオーバーフローは**未定義動作**です。上の例では、実際の機器で起きる「ビット列としての巻き戻り」を再現するために、いったん符号なし整数で加算しています。

## `time_t` を64ビットにすれば済むのか {#time-t-64bit}

`time_t` を64ビットにすれば、表せる範囲は数千億年先まで広がり、実用上は問題になりません。ただし、それだけでは解決しないケースがあります。

- **途中で32ビット変数に代入している**：`int` や `long`（32ビット環境での `long` を含む）に一度入れると、そこで切り捨てられます。
- **データ形式に32ビットの欄がある**：ファイル形式、データベースの列、通信プロトコルのフィールドなど。
- **外部とのやりとり**：ライブラリの ABI（バイナリ互換性）を変えずには型を変えられない場合があります。

このように「どこか1か所でも32ビットに押し込められている」と問題が残るため、見つけるのが難しいのが2038年問題の厄介な点です。
